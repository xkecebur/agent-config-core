# Code of Conduct

## The short version

Be straightforward and be decent. Argue about the claim, not the person making it.

## Expected behaviour

- **Be specific.** "This is wrong because `ADD COLUMN NOT NULL` rewrites the table on PG 10"
  is useful. "This is bad" is not.
- **Assume competence.** Contributors come from different stacks. Someone unfamiliar with
  Spring or Eloquent is not unfamiliar with engineering.
- **Accept correction.** Every module here is a factual claim, and factual claims get
  corrected. That includes the maintainer's.
- **Disagree in the open.** Direct technical disagreement is welcome and expected. Blunt is
  fine; dismissive is not.

## Unacceptable behaviour

- Personal attacks, harassment, or discriminatory remarks of any kind
- Sustained disruption of discussion, or repeatedly reopening a settled decision without
  new evidence
- Publishing someone's private information
- Using this project to distribute offensive-security material, malware, or content designed
  to make an AI agent act against its user's interest
- Sexualised language or imagery, or unwelcome attention of any kind

## Scope

Applies to everything in this repository — issues, pull requests, discussions, commit
messages, and code — and to any space where someone represents this project.

## Enforcement

Report a concern through GitHub's private vulnerability reporting on this repository
(**Security → Report a vulnerability**), which reaches the maintainer privately. Reports are
handled confidentially.

Responses, depending on severity: a correction, a warning, removal of the offending content,
or a block from the repository. Enforcement decisions are the maintainer's, and the reasoning
will be stated rather than left implicit.

This project is maintained by one person. Enforcement is best-effort and may take a few days.
